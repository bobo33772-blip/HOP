# 찜 공구 · 4주 MVP

홈리빙 파일럿 몰 3곳에서 공구 한 번을 처음부터 끝까지 돌리는 최소 시스템입니다.

> **4주 원씽**: 결제가 끝난 수량으로 생산을 결정한 홈리빙 판매자 1곳

찜한 고객에게 초대 문자를 보내고, 결제 없이 신청을 받고, 목표가 차면 쿠폰을 발급하고, 결제된 수량을 집계해 판매자에게 리포트로 넘깁니다.

## 무엇이 들어 있나 (MVP 6개)

| # | 기능 | 파일 | 지키는 규칙 |
|---|---|---|---|
| 1 | 설치·연결 (카페24 OAuth) | `src/http/server.ts` `/oauth/*`, `src/cafe24/real.ts` | 토큰은 AES-256-GCM으로 암호화 저장, state 서명 검사 |
| 2 | 초대 문자 | `src/services/campaigns.ts`, `src/services/messages.ts` | 찜 ∪ 장바구니 중복 제거, **수신 동의자만**, `(광고)` 표기·무료수신거부 번호 필수, **21:00~08:00 발송 금지**, 마감 후 초대 금지 |
| 3 | 위젯 + 결제 없는 신청 | `src/http/widget.js`, `src/services/pledges.ts` | 로그인 회원만(암호화 회원 ID 서버 검증), 1인 한도, 같은 요청 재전송은 한 번만(Idempotency-Key), 마감 전 취소 |
| 4 | 마감 판정 + 쿠폰 | `src/services/judge.ts` | 실제 마감 시각 이후에만, 한 번만 판정. 100명씩 발급 → 발급 내역 대조 → 빠진 회원 재발급 → 그래도 빠지면 '확인할 일'로 남김 |
| 5 | 결제 집계 | `src/services/payments.ts` | 웹훅 본문은 믿지 않고 주문을 카페24에서 다시 조회, 쿠폰 주문만, 입금 전·취소·기한 뒤 결제는 확정에서 제외, 매일 03:00 야간 대사 |
| 6 | 확정 리포트 | `src/services/report.ts`, `src/http/pages.ts` | 결제 완료 기준 확정 수량, 읽기 전용 링크, 회원 ID 등 개인정보 없음 |

사람이 대신하는 부분(운영자 화면 `/admin`)은 다음과 같습니다.
- 찜 많은 상위 20개 상품 목록
- 운영팀이 판매자와 통화하며 하는 공구 개설
- 생산 결정 기록(원씽)
- 4주 판정표

## 실행

Node.js 22.6 이상이 필요하고, 외부 라이브러리는 쓰지 않습니다.

```bash
cd jjim-gonggu
npm test        # 핵심 규칙과 보안 경계 테스트 20개
npm run demo    # 모의 카페24 쇼핑몰로 6단계를 끝까지 눌러 보기 → http://localhost:8787/demo
```

**데모 순서**
1. `/demo`에서 운영자 토큰을 확인하고 운영자 화면에 들어갑니다.
2. 새 공구 탭에서 상품을 고르고, 조건을 입력해 미리보기한 뒤 공구를 엽니다.
3. 상품 페이지로 가서 고객(m62 등)을 고르고 위젯에서 신청합니다.
4. 데모 막대로 시간을 넘기며 마감 판정과 쿠폰 발급을 봅니다.
5. 쿠폰으로 결제한 뒤 '결제 기간 끝으로'를 누릅니다.
6. 운영자 화면에서 확정 리포트를 보고 생산 결정을 기록합니다. 4주 판정표에도 반영됩니다.

실제 카페24 연동으로 실행하는 방법:

```bash
cp .env.example .env   # 값 채우기 (이 파일은 커밋하지 않습니다)
set -a; . ./.env; set +a
npm start
# 판매자가 설치: {PUBLIC_BASE_URL}/oauth/start?mall_id=쇼핑몰ID
```

## 실제 연동 전 1주 차에 확인할 것 (코드의 `VERIFY` 표시)

모의 쇼핑몰로는 전부 검증했습니다. 아래 항목은 공식 문서로 경로만 확인했고, **카페24 테스트몰에서 아직 확인하지 않았습니다.**

| 항목 | 지금 상태 | 확인할 것 |
|---|---|---|
| P2 회원 검증 | 실제 연동에서는 **모든 신청을 거절**(안전한 기본값) | Front SDK 암호화 회원 ID의 서버 검증·복호화 방식 → `RealCafe24.verifyMember`, `widget.js memberToken` |
| P3 쿠폰 | 생성·발급 요청 필드명 추정 | 정액·상품 한정·기간 지정 쿠폰 생성, 1회 발급 인원, 1,000명 발급 누락 0 |
| P7 지정 몰 설치 | 미확인 | 스토어 심사 전에 파일럿 몰에만 설치할 수 있는지. 안 되면 판매자가 직접 쿠폰을 발급하는 수동 방식으로 진행 |
| P8 찜 100명 초과 | 100명까지만 받고 경고를 남김 | 회원별 찜 목록 + 로그인 웹훅(90143) 보완 경로 |
| P9 개인정보 제공 설정 | 미확인 | 몰 설정을 끄면 수신 동의 조회가 막히는지 |
| 주문 웹훅 | 이벤트 90023·90025(결제), 90026·90029(취소)로 가정 | 이벤트 번호, 서명 헤더 이름과 방식(`WEBHOOK_SECRET`), 주문의 결제·취소·쿠폰 필드 |
| SMS | 요청 필드명 추정 | 회원 ID 발송, 수신거부자 자동 제외, LMS 단가 |
| P5 결과 문자 | 수신 동의자에게만, 야간 금지 시간도 지킴 | 정보성인지 법무 확인 |
| 상품 주소 | `{mall}.cafe24.com/product/detail.html` | 독립 도메인을 쓰는 파일럿 몰의 주소 |

## 개인정보 · 보안

- 고객 전화번호·이름·주소는 저장하지 않습니다. 회원 ID만 쓰고, 문자는 카페24 SMS에 회원 ID만 넘깁니다. 테스트가 DB 스키마를 검사합니다.
- 결제금을 받지 않습니다. 결제는 판매자 쇼핑몰 PG에서 처리합니다.
- 운영자 로그인은 HttpOnly·SameSite=Strict 세션 쿠키를 쓰고, 쓰기 요청에는 `X-JJG` 헤더를 요구합니다(CSRF 차단). 로그인과 주요 조작은 `audit_log`에 남깁니다.
- 공개 API는 쿠키를 쓰지 않습니다. 신청 API에는 IP당 분당 호출 한도가 있습니다.
- 판매자 리포트는 추측하기 어려운 토큰 링크로만 열리고, 개인정보가 없습니다.
- 파일럿 전에 몰과 처리 위탁 계약을 맺고, 판매자 개인정보 처리방침에 수탁사로 기재해야 합니다.
- 비밀값(`.env`, DB 파일)은 `.gitignore`로 제외했습니다. 이 저장소는 공개 저장소입니다.
