## 2026-10-08 · 카페24 찜 대신 위젯 &lsquo;공구 알림&rsquo;
- 카페24 답변: 찜 회원 조회에 필요한 개인정보 권한(mall.read_privacy)은 사업자등록과 개인정보 서약서가 있어야 받을 수 있다. 팀은 사업자등록을 할 수 없어 찜 API 없이 간다.
- 상품 페이지 위젯에 &lsquo;공구 열리면 알림 받기&rsquo;를 넣었다. 진행 중 공구가 없거나 지난 공구가 끝난 상품에 보이고, 로그인 회원 ID만 저장한다(`product_alerts`, 마이그레이션 0002).
- 수요 레이더에 상품별 알림 신청 수를 더했고, 공구를 열면 알림 신청 회원을 장바구니 회원과 함께 초대한 뒤 신청을 비운다. 초대 문자 첫마디는 받는 사람에 맞춘다(알림만 / 알림+장바구니 / 장바구니만).
- 운영 DB(Supabase)에 `pnpm db:migrate`로 0002를 적용해야 한다.

## 2026-10-08 · 실제 카페24·운영 배포·심사 준비
- 이름을 찜꽁으로 바꾸고, 판매자가 직접 공구를 여는 웹앱을 만들었다 (기획서의 Go 이후 범위를 심사 대비로 앞당김).
- 테스트몰에서 설치·쿠폰 생성·위젯을 확인했고, 개인정보 권한이 없어 장바구니 고객 공구로 동작한다.
- Vercel(서울) + Supabase(서울) 배포, pg_cron 1분 정기 작업, 매시 결제 대사, 앱 삭제 웹훅, 개인정보 자동 파기.
- 카페24 OpenAPI 스펙 대조로 결제 집계(coupon_code)·문자 발신번호(sender_no)·토큰 동시 갱신 버그를 고쳤다.
- 심사 기간은 카페24 안내 기준 3~5일(길면 1주). 다음: 실제 회원 참여 신청 확인 → 심사 제출 → 심사 기간에 파일럿 3몰 섭외.

## 2026-10-08 · 두 MVP 통합
4주 파일럿 MVP(Node 단독 서버, SQLite)와 스토어 출시용 MVP(Next.js, Drizzle)를 이 앱 하나로 합쳤다.
- 공구 엔진(개설·신청·판정·쿠폰·문자·결제 집계·대사·리포트·판정표)을 Postgres(Drizzle)로 옮기고, 흐름 테스트를 그대로 옮겨 같은 동작을 확인했다.
- 운영자 화면(`/admin`), 판매자 리포트(`/r/<토큰>`), 위젯(`/widget.js` + `/api/public/…`), 데모(`/demo`)를 붙였다.
- 정기 작업: 서버 안 30초(`instrumentation.ts`) 또는 외부 크론(`/api/cron/tick`). 문자는 선점 후 발송해 중복 발송을 막는다.
- 마이그레이션은 운영 DB가 아직 없어 `0000_init` 하나로 새로 만들었다.

## 1단계에서 확정할 것 (테스트몰 PoC)
코드에 `VERIFY` / `⚠ PoC 체크`로 표시해 둔 가정들 (README의 표 참고):
