# 04. 공구 열기 · 취소 확인 창 등 판매자 화면 다듬기

- PR: #130 (#131 · #132 이어서) · 날짜: 2026-10-22 · 담당: 팀원(aksla2013-star), 리드가 데모 서버(3200)에서 보며 피드백

## 문제
- "공구 열기"를 누르면 **바로** 열려서, 쿠폰이 만들어지고 초대 문자가 예약되는 큰 동작을 실수로 할 수 있었어요.
- 휴대폰에서 확인 창이 아래 메뉴 · 데모 "역할 바꾸기"에 가려 버튼을 누를 수 없었어요.
- 상품 목록이 길어 한눈에 보기 어렵고, 대시보드 "다음 공구 후보"에 이미 공구를 연 상품이 또 나왔어요.
- "초대"처럼 실제로는 문자 발송 인원인 칸 이름이 헷갈렸어요.

## 근거
- 리드가 데모 서버를 보며 화면별로 요청한 수정(실시간 UX 작업).

## 결정 (무엇을 만들었나)
- 공구 열기 버튼 → **"공구를 여시겠습니까?" 확인 창**(목표 · 공구가 · 마감, 초대 문자 인원 · 발송 시각). 공구 취소 창도 같은 모양으로 **화면 가운데**에 떠요(`console/center-dialog.module.css`).
- 아래에서 올라오는 창은 휴대폰 아래 메뉴 · 역할 바꾸기보다 위에 떠요.
- 공구 열기 상품 목록: 상위 5개 + "더보기 (N개) ▾".
- 대시보드: 공구가 없으면 "첫 공구 열기" 버튼, "다음 공구 후보"에서 공구를 연 적 있는 상품은 빼요.
- 공구 관리(웹)에서 "고객이 기다리는 상품" 카드를 빼요(같은 숫자는 공구 열기 목록에).
- 칸 이름: "초대" → "문자 발송", "초대→신청" → "문자 발송→신청", 미리보기 세 번째 칸 → **"중복 빼고"**(#132, '제외'는 빠진 인원으로 읽혀서).

## 안 한 것과 이유
- API · DB · `src/lib` 동작은 바꾸지 않았어요(화면 · 문구만).

## 가정 (파일럿에서 확인할 것)
- 확인 창이 한 번 더 누르는 수고보다 실수를 막는 이득이 크다는 것.

## 성공 확인
- 파일럿 판매자가 공구를 잘못 열어 취소하는 일이 없는지.
- 휴대폰에서 모든 확인 창 버튼을 누를 수 있는지(390px).
