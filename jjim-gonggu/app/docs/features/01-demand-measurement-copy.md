# 01. 소개 문구를 '재입고 전 수요 측정'으로

- PR: #123 · 이슈: #122 · 날짜: 2026-10-21 · 담당: 김보성

## 문제
스토어 · README · 앱 첫 화면이 "기다리는 손님이 모이면 **그때 만들어요**"라고 소개해서, 찜꽁이 **생산을 대신 해 주는 앱**처럼 읽혔어요. 판매자가 찜꽁을 쓰는 진짜 이유는 그 앞 단계, "다시 만들어도 팔릴까?"를 **확인**하는 거예요.

## 근거
- 리드 검토(10/21): "품절 상품을 기다리는 손님이 있으면 만드는 게 아니라, 수요 측정에 초점을 둔 것."
- 기획서의 가치 제안도 "찜 · 장바구니에 잠든 수요를 재생산 전에 확정 주문으로 바꾼다"예요.
- 목표를 못 채운 공구도 "아직 수요가 부족하다"는 답이라 실패가 아니에요. 생산 중심 문구로는 이게 설명되지 않아요.

## 결정 (무엇을 만들었나)
- 대표 문구: **"만들기 전에, 진짜 수요부터 확인하세요"** (스토어 헤드라인 · 설명 이미지 · 앱 시작 인트로)
- 장바구니 · 알림 신청은 **관심**, 공구 쿠폰으로 결제된 수량은 **진짜 수요**라고 불러요.
- 스토어 짧은 설명(200바이트 안) · 마케팅 문구 · 상세 설명 첫 문단 · README 첫 줄과 흐름도를 같은 방향으로 바꿨어요.
- 스토어 설명 이미지(740×416)를 새로 만들었어요(같은 분홍 바탕 · 캐릭터).

## 안 한 것과 이유
- "생산 결정 기록" · 4주 원씽("결제된 수량으로 생산을 결정한 판매자 1곳")은 그대로 뒀어요. 수요를 잰 **다음 단계**라 새 문구와 맞아요.
- 판매자 홈 문구 "그때 만들고 파세요"는 #121(새 디자인)에서 이미 빠져 충돌을 피하려고 건드리지 않았어요.

## 가정 (파일럿에서 확인할 것)
- 판매자가 "수요 측정"이라는 말을 자기 문제로 알아듣는다. 파일럿 판매자 첫 통화에서 소개 문구를 읽어 주고 반응을 들어 봐요.

## 성공 확인
- 파일럿 판매자에게 "찜꽁이 뭐 하는 앱 같아요?"라고 물었을 때 "만들기 전에 팔릴지 확인하는 앱"에 가까운 답이 나오는지.
- 카페24 심사 재제출 때 새 문구 · 이미지로 올렸는지.
