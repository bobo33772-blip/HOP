# 기능 기록

새 기능을 **왜** 만들었는지 남기는 곳이에요. PR은 "무엇을 바꿨는지", [DESIGN.md](../DESIGN.md)는 "화면 규칙", 기획서(`../../plans/`)는 "처음 계획"을 담고, 여기는 **문제 · 결정 · 가정 · 성공 확인**을 담아요.

## 언제 쓰나요
- **새 기능을 만들 때만** 써요. 버그 수정 · 문구 한 줄 수정은 쓰지 않아요.
- 가능하면 **만들기 전에** "문제"와 "성공 확인"부터 쓰고, 다 만든 뒤 "결정 · 안 한 것 · 가정"을 채워요.
- 기능이 바뀌면(가정값을 실측으로 바꿨다 등) 그 파일 맨 아래 "바뀐 기록"에 날짜와 함께 한 줄 더해요. 새 파일을 만들지 않아요.
- 기획서는 읽기만 하고 고치지 않아요. 기획서와 달라진 결정은 여기에 적어요.

## 양식 (새 파일은 `NN-영문-이름.md`로, 아래를 복사)

```markdown
# NN. 기능 이름

- PR: #번호 · 이슈: #번호 · 날짜: YYYY-MM-DD · 담당: 이름

## 문제
누가, 어떤 순간에, 무엇 때문에 곤란한가. 한두 문장.

## 근거
그렇게 판단한 이유. 판매자 말 · 데이터 · 리뷰 피드백 · 기획서 어디.

## 결정 (무엇을 만들었나)
판매자가 보는 변화 위주로 3~5줄.

## 안 한 것과 이유
고민했지만 하지 않은 것. 나중에 같은 고민을 반복하지 않게.

## 가정 (파일럿에서 확인할 것)
숫자나 판단 중 아직 실측이 아닌 것. 어디에 적혀 있는지(코드 위치)도.

## 성공 확인
무엇을 보면 잘 됐는지 알 수 있나. 지표 · 확인 방법.

## 남은 일 · 다음 단계

## 바뀐 기록
- YYYY-MM-DD: 처음 씀
```
