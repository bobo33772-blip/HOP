# 찜 공구 서버

자사몰에서 찜하거나 장바구니에 담은 고객을 모아, 목표 수량을 채우면 할인가로 여는 카페24 판매자용 예약 공동구매 앱이에요.
Next.js 하나로 판매자 화면·운영자 화면·고객 위젯·공구 엔진·데이터베이스를 모두 돌려요.

> **4주 원씽**: 결제가 끝난 수량으로 생산을 결정한 홈리빙 판매자 1곳

- 단계별 진행: [docs/ROADMAP.md](docs/ROADMAP.md)
- 카페24 앱 등록 (사용자 작업): [docs/CAFE24_SETUP.md](docs/CAFE24_SETUP.md)

## 빠르게 실행하기 (데모 모드, 키 필요 없음)

```bash
corepack pnpm install
corepack pnpm dev -p 3100
```

`http://localhost:3100/demo` 를 열면 모의 카페24 쇼핑몰(LINEN & CO.)에서 공구 한 번을 끝까지 눌러 볼 수 있어요.

1. 운영자 화면(`/admin`)에서 찜 데이터 모으기 → 상품 선택 → 미리보기 → 공구 열기 (운영자 토큰은 `/demo`에 있어요)
2. 상품 페이지(`/demo/shop/102?member=m62`)에서 고객이 되어 위젯으로 결제 없이 신청
3. 데모 막대로 시간 넘기기: 마감 → 판정·쿠폰 → 쿠폰으로 결제 → 결제 기간 끝 → 확정 리포트(`/r/…`) → 생산 결정 기록 → 4주 판정표

데모 모드는 모의 쇼핑몰과 DB가 메모리에만 있어서 서버를 다시 켜면 처음부터 시작해요. 실제 문자·결제는 일어나지 않아요.

```bash
corepack pnpm test        # 엔진 흐름·규칙·카페24 연동·라우트 테스트
corepack pnpm typecheck
```

## 화면과 주소

| 누가 | 주소 | 내용 |
|---|---|---|
| 판매자 | `/` · `/radar` | 카페24 관리자에서 앱 실행(`/api/cafe24/launch`) → 연결 상태, 내 공구, 수요 레이더 |
| 운영자 | `/admin` | 공구 목록·상세(문자·확인할 일·수동 판정·대사), 새 공구, 4주 판정표. 파일럿 기간에는 판매자 앱 대신 운영팀이 씀 |
| 판매자 (링크) | `/r/<토큰>` | 읽기 전용 확정 리포트. 개인정보 없음 |
| 고객 | `/widget.js` | 쇼핑몰 상품 페이지에 스크립트 태그로 붙는 진행률 + 결제 없는 신청 위젯 |
| 위젯 API | `/api/public/…` | 공구 정보, 신청(Idempotency-Key), 내 신청, 취소. CORS 열림, 쿠키 없음 |
| 카페24 | `/api/cafe24/launch` · `callback` · `install` · `webhooks` | 앱 실행(HMAC 검증), OAuth, 운영팀 직접 설치, 웹훅 |
| 크론 | `POST /api/cron/tick` | 외부 크론용 정기 작업 (`CRON_SECRET` 필요) |

## 공구 엔진이 지키는 규칙

| # | 기능 | 파일 | 규칙 |
|---|---|---|---|
| F1 | 설치·연결 | `src/app/api/cafe24/*`, `src/lib/malls.ts` | 앱 실행 HMAC 검증(±2시간), OAuth state 1회용, 토큰 AES-256-GCM 암호화 저장 |
| F2 | 수요 레이더 | `src/lib/radar.ts` | 숫자(count)만 먼저, 회원 목록·수신동의 대조는 공구를 열 상품에서만 |
| F3·F4 | 개설·초대 | `src/lib/engine/campaigns.ts` | 쿠폰을 먼저 만들고 실패하면 아무것도 저장 안 함, 찜 ∪ 장바구니 중복 제거, **수신 동의자만**, `(광고)`·무료수신거부 번호 강제, **21:00~08:00 발송 금지**, 마감 후 초대 금지 |
| F5·F6 | 위젯·신청 | `public/widget.js`, `src/lib/engine/pledges.ts` | 로그인 회원만(암호화 회원 ID 서버 검증), 1인 한도, 재전송은 한 번만, 마감 전 취소 |
| F7·F8 | 판정·쿠폰 | `src/lib/engine/judge.ts` | 실제 마감 시각 이후에만 한 번만 판정, 100명씩 발급 → 발급 내역 대조 → 빠진 회원 재발급 → 그래도 빠지면 '확인할 일' |
| F9 | 결제 집계 | `src/lib/engine/payments.ts` | 웹훅 본문은 믿지 않고 주문을 다시 조회, 쿠폰 주문만, 입금 전·취소·기한 뒤 결제는 확정 제외, 매일 03:00 대사 |
| F10 | 확정 리포트 | `src/lib/engine/report.ts`, `src/app/r/[token]` | 결제 완료 기준 확정 수량, 4주 판정표 |

정기 작업(`src/lib/engine/scheduler.ts`)은 예약 문자 → 마감 판정 → 결제 기간 종료 → 결과 문자 순으로 돌아요.
기본은 서버 안에서 30초마다(`src/instrumentation.ts`), 서버를 여러 대 띄우면 `SCHEDULER=off` + 외부 크론이에요. 문자는 보내기 전에 선점해서 두 번 나가지 않아요.

## 폴더 구조

```
src/lib/core      공구 규칙 (개설 검증, 신청, 광고 문자, 요금) — 외부 의존 없음
src/lib/engine    공구 엔진 (개설·신청·판정·문자·결제 집계·리포트·정기 작업) — Ctx(db, shop, clock)를 주입받음
src/lib/cafe24    카페24 OAuth·HMAC·API 호출기·모의 쇼핑몰
src/lib/server.ts 서버 전역 컨텍스트 (연동 모드 / 데모 모드)
src/db            Drizzle 스키마 (Postgres / 로컬 PGlite)
src/app           화면과 API
public/widget.js  쇼핑몰 상품 페이지 위젯 (의존성 없음)
drizzle/          마이그레이션 SQL (pnpm db:generate)
tests/            vitest
```

## 실제 카페24 연동 전에 확인할 것 (PoC, 코드의 `VERIFY` 표시)

모의 쇼핑몰로는 전부 검증했어요. 아래는 공식 문서로 경로만 확인했고 **카페24 테스트몰에서 아직 확인하지 않은** 부분이에요.

| 항목 | 지금 상태 | 확인할 것 |
|---|---|---|
| P2 회원 검증 | 실제 연동에서는 **모든 신청을 거절**(안전한 기본값) | Front SDK 암호화 회원 ID의 서버 검증 방식 → `Cafe24Api.verifyMember`, `widget.js memberToken` |
| P3 쿠폰 | 생성·발급 요청 필드명 추정 | 정액·상품 한정·기간 지정 쿠폰, 1회 발급 인원, 1,000명 발급 누락 0 |
| P7 지정 몰 설치 | 미확인 | 스토어 심사 전 파일럿 몰에만 설치 가능한지 (`/api/cafe24/install`) |
| P8 찜 100명 초과 | 100명까지만 받음 | 회원별 찜 목록 + 로그인 웹훅(90143) 보완 경로 |
| P9 개인정보 제공 설정 | 미확인 | 몰 설정을 끄면 수신 동의 조회가 막히는지 |
| 주문 웹훅 | 90023·90025(결제), 90026·90029(취소) 가정 | 이벤트 번호, `X-API-Key` 검증 방식, 주문의 결제·취소·쿠폰 필드 |
| SMS | 요청 필드명 추정 | 회원 ID 발송, 수신거부자 자동 제외, LMS 단가 |
| P5 결과 문자 | 수신 동의자에게만, 야간 금지 시간도 지킴 | 정보성인지 법무 확인 |
| 상품 주소 | `{mall}.cafe24.com/product/detail.html` | 독립 도메인을 쓰는 파일럿 몰의 주소 |

## 개인정보 · 보안

- 고객 전화번호·이름·주소는 저장하지 않아요. 회원 ID만 쓰고, 문자는 카페24 SMS에 회원 ID만 넘겨요. 테스트가 DB 열 이름을 검사해요.
- 결제금을 받지 않아요. 결제는 판매자 쇼핑몰 PG에서 처리해요.
- 운영자 로그인은 서명된 HttpOnly·SameSite=Strict 쿠키, 쓰기 요청에는 `X-JJG` 헤더 필수(CSRF 차단). 로그인과 주요 조작은 `audit_logs`에 남아요.
- 공개 API는 쿠키를 쓰지 않고, 신청 API에는 IP당 분당 호출 한도가 있어요. 공개 응답에 쿠폰 번호·원가는 넣지 않아요.
- 판매자 리포트는 추측하기 어려운 토큰 링크로만 열리고 개인정보가 없어요.
- 파일럿 전에 몰과 처리 위탁 계약을 맺고, 판매자 개인정보 처리방침에 수탁사로 기재해야 해요.
- `.env`, `.env.local`, `.data/`는 커밋하지 않아요. 이 저장소는 공개 저장소예요.
